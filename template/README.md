# Company Agents — プロダクトワークスペース

このフォルダ1つで完結する仮想会社。Claude Code で秘書に話しかけるだけで、会議と開発が回る。

---

## 使い方

```bash
cd このフォルダ/
claude
```

秘書が起動する。「発散会議を開いて」で開始。

---

## できること

| 言葉 | 何が起きるか |
|---|---|
| 「発散会議を開いて」 | アイデアを広げる（3エージェント） |
| 「選択会議を開いて」 | アイデアを検証・絞る（4エージェント） |
| 「要件定義会議を開いて」 | 仕様を固める（6エージェント） |
| 「開発を始めて」 | 設計→実装→テスト→リリースを順に実行 |
| 「進捗は？」 | ダッシュボード表示 |
| 「詳しく調べて」 | Deepリサーチ |

## フォルダ構成

```
product/
├── CLAUDE.md              ← ブートローダー（Claude Codeが最初に読む）
├── meta.json              ← 状態管理
├── README.md              ← このファイル
│
├── .company/              ← 会社定義（ルール・エージェント）
│   ├── vision/            　 経営理念
│   ├── secretary/         　 秘書室（振る舞い定義 + メモ保存先）
│   ├── meetings/agents/   　 会議エージェント定義
│   ├── departments/       　 開発ロール定義
│   ├── audit/             　 監査室
│   ├── templates/         　 テンプレート集
│   └── research/          　 リサーチスキル定義
│
├── meetings/              ← 会議ログ保存先
│   ├── 01_ideation/logs/
│   ├── 02_selection/logs/
│   ├── 03_requirements/logs/
│   └── research/
│
└── dev/                   ← 開発成果物保存先
    ├── 01_requirements/
    ├── 02_basic_design/
    ├── 03_detailed_design/
    ├── 04_implementation/
    ├── 05_acceptance/
    └── 06_release/
```

## 全体フロー

```
Ken「発散会議を開いて」
  → 秘書が .company/meetings/agents/ideation.md を読み込み
  → 3エージェントでアイデア発散

Ken「選択会議を開いて」
  → 秘書が selection.md を読み込み
  → 4エージェントで検証 → Kenが判断

Ken「要件定義会議を開いて」
  → 秘書が requirements.md を読み込み
  → Phase A(検証) → Phase B(定義) → 要件定義書出力

Ken「開発を始めて」
  → 秘書が departments/{role}/CLAUDE.md を1つずつ読み込み
  → 作業 → 監査(PASS/FAIL) → 次工程
```

## エージェント一覧

### 会議エージェント（会議中のみ登場）

| 名前 | 会議 | 一言 |
|---|---|---|
| 🏛 ビジョン番人 | 発散 | ビジョンから外れたら即指摘。それ以外は黙る |
| 🖼 アナロジー職人 | 発散 | 他業界の類似事例を3つ以上出す |
| 👤 ユーザー代弁者 | 発散・要件定義 | ユーザー行動シナリオで具体化 |
| 💀 破壊チーム | 選択・要件定義 | 失敗理由を1つだけ挙げる |
| 📊 数字ハンター | 選択 | 数字で裏付ける。数字なき主張を通さない |
| 🔮 5-Whys | 選択・要件定義 | 「なぜ？」を5回掘る |
| 📦 シンセサイザー | 選択・要件定義 | 最後にKenの判断を構造化 |
| 📋 PM Agent | 要件定義 | ユーザーストーリー・スコープ定義 |
| ⚙ 技術Agent | 要件定義 | 工数評価・技術リスク判定 |

### 開発ロール（秘書が1工程ずつ担当）

| ロール | 工程 | やること |
|---|---|---|
| PM | 01_requirements | 要件定義書の最終化 |
| Architect | 02_basic_design | 技術スタック・システム構成図 |
| Senior Engineer | 03_detailed_design | クラス図・DBスキーマ・テスト戦略 |
| Engineer | 04_implementation | コード実装・単体テスト |
| QA Lead | 05_acceptance | 受け入れ条件の検証 |
| DevOps | 06_release | デプロイ・リリース |

### 監査室

各工程完了後に自動実行。定義書整合・セキュリティ・ビジョンの3観点でPASS/FAIL。

---

## セットアップ

1. このテンプレートをコピーしてプロダクト名をつける
2. `.company/vision/` にミッション・価値観・原則を記入（空でも動く）
3. `claude` で起動
