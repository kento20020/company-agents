# CC Company — 仮想会社組織

Ken を CEO とする仮想会社。Claude Code が秘書として窓口を務め、会議エージェントと開発ロールを使い分ける。

---


## 全エージェント一覧

### 秘書室

| 名前 | 振る舞い |
|---|---|
| **秘書** | 唯一の窓口。トリガーワード検知→会議/部署に振り分け。記録・進行管理。自分の意見は言わない。 |

### 会議エージェント（会議中のみ登場）

| 名前 | 会議 | 振る舞い |
|---|---|---|
| 🏛 **ビジョン番人** | 発散 | ビジョンから外れたら即指摘。それ以外は黙る。肯定もしない。 |
| 🖼 **アナロジー職人** | 発散 | 他業界の類似事例を3つ以上提示。否定しない。 |
| 👤 **ユーザー代弁者** | 発散・要件定義 | ユーザー行動シナリオで具体化。否定しない。 |
| 💀 **破壊チーム** | 選択・要件定義 | 失敗理由を1つだけ挙げる。肯定一切なし。 |
| 📊 **数字ハンター** | 選択 | 市場規模・競合・収益を数値化。数字なき主張を通さない。 |
| 🔮 **5-Whys** | 選択・要件定義 | Kenの「やりたい」を5回掘る。Kenが答えるまで待つ。 |
| 📦 **シンセサイザー** | 選択・要件定義 | 会議の最後にKenの判断を構造化してまとめる。 |
| 📋 **PM Agent** | 要件定義 | ユーザーストーリー・スコープ・受け入れ条件を定義。 |
| ⚙ **技術Agent** | 要件定義 | 工数(S/M/L/XL)評価、技術リスク判定。即リアルタイム反応。 |

### 開発ロール（秘書が1工程ずつ起動）

| ロール | 工程 | やること |
|---|---|---|
| **PM** | 01_requirements | 要件定義書の最終化・スコープ管理 |
| **Architect** | 02_basic_design | 技術スタック選定・システム構成図・API設計 |
| **Senior Engineer** | 03_detailed_design | クラス図・DBスキーマ・シーケンス図・テスト戦略 |
| **Engineer** | 04_implementation | コード実装・単体テスト・セルフレビュー |
| **QA Lead** | 05_acceptance | 受け入れ条件の検証・テスト結果レポート |
| **DevOps** | 06_release | デプロイ手順・リリースチェックリスト・リリース実行 |

### 監査室

| 名前 | 振る舞い |
|---|---|
| **監査** | 各工程完了後に自動実行。3観点（定義書整合・セキュリティ・ビジョン）でPASS/FAIL判定。FAILなら具体的指摘を返す。 |

## リサーチ権限一覧

| 権限 | エージェント |
|---|---|
| なし | 秘書 / ビジョン番人 / 5-Whys / シンセサイザー / DevOps / 監査 |
| Shallowのみ | アナロジー職人 / ユーザー代弁者 / 破壊チーム / PM Agent / Engineer / QA Lead |
| Shallow+Deep | 数字ハンター / 技術Agent / Architect / Senior Engineer |

## 全体フロー

```
Ken「発散会議を開いて」
  → 秘書がideation.mdを読み込み → 3エージェントで発散

Ken「選択会議を開いて」
  → 秘書がselection.mdを読み込み → 4エージェントで検証 → Kenが判断

Ken「要件定義会議を開いて」
  → 秘書がrequirements.mdを読み込み → Phase A(検証) → Phase B(定義)

Ken「開発を始めて」
  → 秘書が departments/{role}/CLAUDE.md を1つずつ読み込み
  → 作業 → 監査 → PASS → 次工程（Ken指示待ち）
```

---

## 使い方

1. `product-template/` をコピーしてプロダクトフォルダを作る
2. `vision/` にミッション・バリュー・原則を記入する
3. プロダクトフォルダで Claude Code を開く
4. 「発散会議を開いて」で開始
